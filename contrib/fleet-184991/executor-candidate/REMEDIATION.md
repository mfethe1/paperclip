# Executor remediation of independent a3bb8cd review

**Local-only fail-closed candidate. Execution remains disabled. F1 and fleet enablement remain blocked.**

## Changes and regression contracts

- **F2 — existing ledger identity/schema:** new ledgers are exclusively created with owner-only permissions, application ID `0x50434558`, schema version 2 and a committed exact schema. Existing files are inspected read-only before any persistent pragma/schema mutation. All sqlite_master object definitions, indexes, triggers, integrity and foreign keys must match. Unrecognized, incomplete or original unversioned ledgers are rejected unchanged; there is no implicit migration/repair. Tests replace the partial unique index, replace the receipt trigger, reset schema identity, and supply an unrelated DB, checking byte preservation.
- **F3 — protected path/read:** no-follow directory-FD ancestor traversal; reject group/world-writable ancestors, unsafe owner/mode, symlink, nonregular, oversized and multi-link files. Configuration is parsed from the same verified bounded FD, never a pathname reopen. Ledger parent must be service-private; retain FDs and compare directory/file inode identity around SQLite opens before writes. Regression trace replaces each path at the review scheduling boundary and proves no target mutation / no unchecked JSON returned. FIFO, directory, hardlink, unsafe-parent and symlink-parent cases reject.
- **F4 — one terminal contract:** exact receipt fields/version/types, request identity, integer fence/exit, finite chronological timestamps, deadline-constrained start/success, safe bounded artifact names/hashes, exact request-bound typed task-verification evidence. The writer validates before receipt insertion/state commit; lookup and success verification apply the same validator. Malformed evidence leaves the attempt running. Synthetic valid receipt tests remain unit tests, not runtime qualification.
- **F5 — supervised stop required:** there is no qualified supervisor-stop/provider-revocation channel in this candidate. Therefore every otherwise valid requested release from `running` (success, failure, cancellation) becomes signed `unknown`, retaining the issue reservation. Accepted/no-spawn cancellation can release; a running assertion cannot. The diagnostic runner explicitly reports `boundary_stop_proven: false`; ordinary process-group cleanup is never a containment proof.
- **F6 — post-deadline status:** fresh Ed25519 `status-v2` grants authenticate exact company/project/attempt/request digest independently of expired `submit-v2` grants. Separate status operation uses a read-only ledger connection and performs no reconciliation/admission/state changes. Cross-tenant, wrong digest and cross-domain grants reject. CLI status exit 0 means authenticated transport success, not task success.
- **F7 — exact types / bounded IO:** reject overflow JSON floats (`1e999`), boolean/float lineage depth and nonfinite/out-of-range numeric values; one EOF-delimited input frame is capped at 64 KiB and 2 seconds even if a pipe remains open. Diagnostic stdout/stderr use capped memory pipes, kill ordinary process group on overflow, and expose truncation/output-limit flags instead of unbounded temporary disk files.
- **Authority separation:** available established `cryptography` 46.0.4 Ed25519 verifier uses controller public bytes only. Executor no longer exposes a grant-minting helper. Private signing helpers/keys are test-only disposable fixtures. Missing dependency fails authentication closed. Receipt HMAC remains a distinct supervisor-owned key; deployment must isolate it from workers. Public bytes cannot forge submit grants; status signatures cannot authorize submission.

## Named remaining blockers / required parent integration

1. **F1 TRUSTED_PAPERCLIP_INGRESS:** Paperclip's installed process adapter does not send this stdin transport. Nothing was edited in node_modules and no adapter was registered. Parent must supply a reviewed fixed wrapper that obtains a signed immutable request from a trusted controller channel, bound to the real Paperclip company/project/issue/run context; environment identifiers are correlation hints, not authority. Wrapper must not mint grants or accept worker-controlled prompts as authorization. Until that exists the CLI is a local transport only.
2. **SUPERVISED_STOP_CHANNEL:** qualify isolated worker process/resource boundary, detached-tree stop and host broker credential revocation. Implement independently authenticated stop evidence bound to request digest/attempt/fence before permitting any running release. Current behavior deliberately has no such release capability.
3. **PROTECTED_SERVICE_IDENTITY:** dedicated service-owned directories/key store/runtime dependency/interpreter and a different nonprivileged worker UID are required. Directory checks plus inode comparisons are not a proof against a malicious concurrent same-UID process swapping a SQLite pathname away and back, or modifying service files. Python sqlite3 cannot provide an arbitrary pre-opened-FD VFS here. Same-UID isolation remains unqualified.
4. **EXACT_RUNNER_AND_BROKER:** approved real gpt-6.1-sol/openai-codex runner, narrow host-owned OAuth broker and real artifacts/model/provider evidence remain absent. No task execution backend has been enabled.
5. **EXACT_SHA_INDEPENDENT_REVIEW:** security-sensitive changes need a new independent review of the resulting commit and parent rerun before any registration/enablement. No operational/runtime/API writes, auth enrollment, dependency installs, pushes, registry mutations or changes to Astra/GLM/bridge holds occurred.

Original OS sandbox evidence was not rerun or promoted. This is remediation code and local tests, not a working fleet executor. The requested bounded execution window was exceeded while resolving verification/environment issues; no operational work was performed to compensate.
